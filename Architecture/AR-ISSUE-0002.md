# 架構評估｜ISSUE-0002

執行者：Codex（SA，自評）；等級 L3；結論：有條件採用。

現況：`src/Excelopen/Excelopen.csproj` 是 net472／net10.0 函式庫，Release 目標已有分類複製設定；現場無 publish 目錄。COM 用戶載入 DLL，無專屬常駐執行檔；外部宿主是否載入 DLL 無法僅以程序名稱確定。

方案 A（採用，使用者於 2026-11-14 確認）：以專案既有目標在 `publish/bin/<框架>` 輸出元件，並將手冊、VBS、LabVIEW 及媒體複製至 Manual、Examples、Media。優點是建置與交付位置一致；風險為覆寫既有檔案和過期檔殘留，須檢查目標、記錄驗證並保留來源。方案 B：維持 bin 輸出並手動整理，改動較少但易遺漏及混用版本，不採用。

不改 COM 介面、套件、執行架構或資料儲存；無資料庫 migration。版本以 1.2.4 為正式版基準，使用時間戳測試版，組件數字版本保持 1.2.4.0，資訊版本及 GetVersionInfo 顯示完整字串。發布前檢查目標路徑與相關載入；首次不存在目標時無舊 DLL 需覆寫。回復方式：保留來源檔，移除或還原本次產出後重建。跨系統 COM 實際載入和 LibreOffice 整合需另行驗收。

符合性：待建置及輸出驗證後記錄。使用者已確認上述分類與正式版基準；本評估記錄該方案及風險。

實作後自查：分類、版本與既定方案一致；實際 COM 宿主和 LibreOffice 整合仍未驗證。為避免刪除使用者檔案，建置不清除既有輸出，舊相依檔須人工檢查。
