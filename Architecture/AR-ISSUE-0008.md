# ISSUE-0008｜跨環境打包與序號架構評估草案 v0.1

SA／系統整合／維運：Codex 依序執行，自查非獨立審查。需求：Requirements/RS-ISSUE-0008.md；狀態：使用者已核准 v0.1；結論：有條件採用。

## 現況與限制
Installer/PackageVersion.ps1 掃描工作區的 `.tools/package-versions` 與 `publish/Installer/Setup`，以工作區路徑決定命名互斥鎖；保證不跨機器或工作區。Installer/FileVersion.ps1 另檢查 DLL 版本台帳、來源雜湊與本機 COM。GitHub hosted runner 為暫時環境，不能以本機鎖或 artifact 保存狀態來保證跨執行唯一性。此前預檢 fixture 因讀取主機 COM 發生衝突，需明確隔離驗證，不得繞過正式防護。

## 選項
| 選項 | 優點 | 限制 |
| --- | --- | --- |
| A：GitHub 持久保留參照統一配號，雲端及本機共用 | 沿用日期序號及本機打包；以原子建立防併行 | 需要受限寫入權限、初始化及刪除保護；GitHub 故障時停止 |
| B：只允許 GitHub 打包，以單一 workflow 執行編號做識別 | 整合較少 | 改變現有日期序號契約，重跑識別及既有本機流程仍需重設 |
| C：沿用各工作區本機鎖 | 改動少 | 無法避免跨機器重複，不符合需求 |

推薦 A：使用專用命名空間中不可覆寫、不可刪除的 Git ref 作配號紀錄，逐日遞增。保留時以原子建立成功作唯一分配依據；競爭或逾時需核對紀錄後安全重試，不能把未知結果當失敗並重用。ref 必須指向可稽核提交並保存日期、序號、來源識別及狀態；具體存放方式在實作前確定與驗證。所有生產性本機及 CI 打包均使用同一權威，拒絕無法連線或權限不足的情況。若無法限制或偵測 refs 遭刪改，不宣稱可保證唯一。

## 遷移與恢復
先盤點所有已用、保留、失敗、部分產物紀錄，包含工作區以外的已知來源；建立可審核高水位及初始化記錄後方可切換。若無法確定所有來源，停止切換並請人類協助；舊檔與台帳保持不變。移轉需測試乾跑、衝突、重複執行與回退。切換後失敗、取消、刪除 artifact 均不釋放序號；失聯或不明結果查驗服務端後處理。若需回退，保留新舊配號紀錄且停止獨立配號，直到能重新確認高水位。

## 安全與維運
工作流程最小權限；不在不可信 pull request 上配置能分配序號或發布的憑證。分配 ref 應有限制建立、刪除及改寫的保護，記錄操作者及執行識別；實際 GitHub 支援能力與儲存庫設定待查證，若不足則重新設計。雲端僅上傳測試 artifact，不自動建立 Release。檢查依賴取得的版本和可信度；輸出 logs、manifest、SHA 與 commit 對照。artifact 可能過期，配號紀錄不可依賴 artifact 留存。發生斷線、衝突、配號不明或權限不足時停止並回報。實作後架構符合性、維運就緒和端對端測試均待執行。
