## 現況與建議
現況：COM 呼叫端 → IDispatch `IExcelOperator`（DispId 1–26）→ ExcelOperator → ClosedXML 0.105.0 → xlsx；專案目標 net472 與 net10.0，COM 註冊與部署另由現有機制處理。現有方法支援儲存格位址與行列。

建議：沿用相同資料流，新增兩個 RGB 字型顏色方法，保留原介面方法及 DispId；使用整數以利自動化呼叫。錯誤透過既有例外途徑回報；新增方法的實際 COM 型別資訊及舊客戶端相容性必須驗證，不能單憑保留 DispId 宣稱相容。

## 方案比較
| 方案 | 效益 | 代價與風險 |
| --- | --- | --- |
| A：增列 RGB 方法 | 複用現有 API 與 ClosedXML；同時滿足位址和行列使用方式 | COM 型別庫及舊客戶端仍需實測；不支援主題色 |
| B：新增通用格式物件 | 可擴展其他格式 | 跨 COM 的物件契約與相容性更複雜，超出目前需求 |
| C：維持現況 | 無介面變更 | 無法設定文字顏色 |

推薦 A，有條件採用，須取得人類核准需求與方案後開發。此項局部介面擴充暫不另建跨需求 ADR。
