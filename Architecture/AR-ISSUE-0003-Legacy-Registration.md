# 舊版 COM 註冊處理方案｜ISSUE-0003

版本：v0.1，待人類核准；Codex（PM／SA 自查）；2026-11-15。

## 現況與目標
使用者要求偵測到舊版 DLL 時詢問是否先移除再重新安裝。本機可確認 32／64 位元既有 ExcelKit COM 均指向 `C:\Users\ryan_\source\repos\Excelopen\Excelopen\bin\Debug\net472\ExcelKit.DLL`，組件版本 1.2.0.0，檔案存在；目前未找到名稱包含 ExcelKit／Excelopen 的解除安裝項目。無法證明其他程式沒有依賴它。

## 建議方案
1. 安裝器偵測可辨識的既有 ExcelKit COM 時，列出位元數、版本與來源位置，詢問使用者是否先移除舊版 COM 註冊後繼續。明示將影響依賴舊 COM 的其他程式，不刪除舊 DLL 或其所在資料夾。選否則保持現況並停止。
2. 只在能確定 ProgID、CLSID、版本、DLL 檔案及登錄位置一致、RegAsm 可用且具管理員權限時提供轉換；不明來源、使用者層覆寫、缺少 DLL、異常或多版本狀態須停止並保留原狀，不自行接管。
3. 動作前建立可驗證的備份及回復資料，範圍須涵蓋兩種位元視圖、ProgID、CLSID、Interface 與 TypeLib 等 RegAsm 實際可能變動的項目；先在隔離環境測定完整範圍與回復方法，不能僅匯出單一登錄機碼就宣稱可還原。
4. 使用舊 DLL 對應的 32／64 位元 RegAsm 逐一解除舊註冊，核對結果後安裝新元件；任一步失敗時停止並依驗證過的回復流程恢復舊設定，記錄結果。若無法安全回復，須清楚告知而非宣稱回復成功。
5. 使用者確認要移除的是舊 COM 註冊；不刪除舊版 DLL、使用者資料，也不假設存在舊版卸載程式。升級、已開啟的 COM 宿主及其他消費者應列入提示與測試。

## 驗收與限制
必須在可還原隔離 Windows 環境驗證選是／否、雙位元、原有消費者、部分失敗、回復與中斷；目前沒有虛擬機，此類測試不能宣稱通過。建議先保留現有阻擋行為，直到處理方案核准、實作及隔離測試完成。雙語功能可先獨立交付未驗證測試版。

## 人類核准與執行狀態
使用者於 2026-11-15 核准本 v0.1 方案並要求重新打包。依第 3 點，必須先在隔離環境測定完整登錄影響與回復；目前無可用環境，因此尚不能啟用移除、替換或保證回復。先完成唯讀偵測、呈現來源與雙語提示；不得將尚未驗證的移除能力標示為已完成。

## COM 交易設計與符合性（2026-11-15）
延續使用者已核准的舊版移除與備份回復方案，改由 `Installer/ComTransaction.ps1` 集中管理兩個位元視圖及固定產品 GUID 的登錄資料。手動舊版採實際已確認的 1.2.0.0 DLL 指紋，未知版本保守停止；先建立受 ACL 保護、有雜湊的 CLIXML 備份，再執行舊 DLL `/unregister`，清理已驗證的產品 Interface／TypeLib，最後註冊新元件。回復保留值型態及 DACL，另保留原元件檔供同目錄升級回復。登錄擁有者 SID／稽核規則未宣稱精確備份，恢復以資料及 DACL 為驗證範圍。

已修正 Inno ssPostInstall 錯誤仍可能導致結束碼 0 的問題：記錄失敗狀態、顯示失敗、回傳非零並由 DeinitializeSetup 回復。已完成交易不允許回滾；未完成交易阻擋下一次操作並顯示備份位置。異常斷電不等同可捕捉的註冊失敗，文件提供手動回復入口且不宣稱整機原子回復。最終符合性以對應 Sandbox 整合測試報告為準。
