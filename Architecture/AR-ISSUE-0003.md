# 架構評估草案｜ISSUE-0003

版本 v0.2；Codex（SA、系統整合及維運，自評）；狀態待核准。現況依據：feature/ISSUE-0002-publish 未提交工作、src/Excelopen/Excelopen.csproj、Class1.cs、Reference/Manual/ExcelKit_User_Manual.md；正式版基準 1.2.4。應用程式碼 src/Excelopen，既有發布位置 publish，安裝檔建議 publish/Installer；安裝測試版號於建置前決定。

## 現況與提案
現況：publish → 使用者手動複製 → 管理員以對應 x86／x64 RegAsm 註冊 net472 → COM 用戶端。net10 為獨立 .NET 元件，不以 RegAsm 註冊。

提案：Release 輸出 → Inno Setup 腳本 → 安裝檔 → 系統安裝目錄 → 前置條件及衝突檢查 → x86／x64 RegAsm 註冊 → 客戶端；解除安裝先驗證所有權，再解除註冊並移除安裝檔案。64 位元系統註冊兩個視圖；32 位元系統只註冊 32 位元。非管理員提示提升權限。安裝程式讀取明確輸入資料夾，不把自身產物納入。可維護的 Inno Setup 設定來源置於專案，並將可使用的設定副本與建置說明置於 publish/Installer，從該目錄以相對路徑參照同層發布內容，安裝檔也輸出至此。

## 方案比較
A：延續手動安裝；實作成本低，但不符合自動註冊及卸載需求。B：Inno + RegAsm，符合需求，但須控制登錄檔所有權、錯誤回復及版本升級；建議採用 B。避免用原生 COM regserver 取代 .NET RegAsm。

## 風險及必要條件
- 偵測到兩個 HKLM 視圖現有 ProgID，CLSID {87654321-4321-4321-4321-210987654321} 指向 1.2.0.0 的既有 Debug DLL。任何測試覆寫或無條件解除註冊都可能影響使用者原有工作。建議安裝器預設偵測並拒絕接管不屬本安裝的註冊；升級只處理能證明屬同一安裝的註冊。
- 一個位元註冊成功、另一個失敗時，須避免報成功，且只回復安裝器本次建立的註冊；解除註冊失敗須有可診斷與重試方式。註冊所有權與失敗回復須在實作和測試設計中驗證。
- 系統 .NET Framework 至少 4.7.2；安裝器需檢查並提示。既有 LibreOffice 為外部相依，不隨包安裝。簽章和企業派送不含於範圍。
- 目前未找到可用隔離 VM，工作程序非管理員；在有既有註冊的主機執行全域安裝測試不安全。建議使用可還原快照的乾淨 Windows VM；獨立 32 位元 Windows 測試仍需該系統。

## 測試與維運
測試計畫包括 32／64 位元 COM 實際呼叫、安裝與卸載、既有註冊衝突、升級、錯誤注入與回復，詳見 TestPlans/TP-ISSUE-0003.md。記錄執行環境、安裝日誌和登錄檔結果，保留使用者資料。無資料庫 migration；安全回復與升級為必要驗證。

結論：有條件採用方案 B；需使用者核准本草案與需求版本、提供或確認隔離測試環境，且正式開發前完成測試計畫。實作後符合性：未執行。


使用者於 2026-11-14 核准 v0.2 並要求選擇 x86 或 x64：安裝時選擇一個或兩個 COM 位元；32 位元 Windows 不提供 x64。此為對已核准方案的明確補充，實際註冊僅限所選項。


## 2026-11-14 實作後自查
已加入同目錄安裝擁有者標記、ProgID 與 CodeBase 的保守比對，以允許可辨識的重新安裝／升級；升級不允許取消已安裝位元選項。八種純判定情況在 Inno Pascal 測試工具通過；真實登錄、升級中斷回復及解除安裝仍未驗證，整體架構符合性不能判定通過。

## 分類後的發布目錄
使用者於 2026-11-15 指示將安裝程式與 Inno 設定分開：`publish/Installer/Setup/` 為安裝程式固定輸出，`publish/Installer/Config/` 保存 `.iss` 及說明。這是已核准發布分類的具體調整，不變更 COM 遷移方案；驗證設定副本能由新位置編譯且不包含安裝程式目錄。
