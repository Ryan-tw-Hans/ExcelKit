# ISSUE-0005 DLL 檔案版本規則需求草案 v0.1

狀態：待核准；PM：Codex。分類：變更；L3：涉及 COM 跨程式相容與安裝打包。與 ISSUE-0004 相關。

## 目標及範圍
使用者要求每次更新時 DLL 檔案版本遞增，確認 COM 相容後重新測試並打包。現有正式基準 `1.2.4`，可見的歷次 build 報告與目前來源的 FileVersion 均 `1.2.4.0`；組件版本亦 `1.2.4.0`。其他位置的歷史版本未知。

## 建議規則與驗收
1. 檔案版本為 `<正式基準 major.minor.patch>.<修訂序號>`，例如下個可用版本候選 `1.2.4.1`；數字以數值比較，不使用字串排序。第 4 欄每次產生內容或行為有更新的測試版時遞增；相同來源重建不自動產生新版本。正式基準更新時前三欄隨基準變動，並須高於先前檔案版本；超過版本欄位上限或無法證明較新時停止並報告，不回繞。
2. 固定來源記錄已分配的最高檔案版本；分配前比對專案留存的 build 報告、當前來源與可讀的已安裝 DLL，不覆用既有版本；資訊不足或多分支版本衝突應停止並協調，不能保證未集中保管的其他機器上版本唯一。打包預檢拒絕較舊、衝突或重用於不同元件版本的數值，測試時用隔離副本，不改動既有產物。多個發行端必須先整合唯一版本台帳，不宣稱離線跨機全域自動遞增。
3. 為維持目前 COM 身分，AssemblyVersion 保持 `1.2.4.0`；只改 FileVersion，產品版本維持 `<正式基準>+台北時間戳`。不改 ProgID、CLSID、IID、型別庫識別及舊 DispId／簽章。這是降低風險，必須以實測而非僅靜態比對確認相容。
4. 新舊 x86／x64 COM 客戶端與註冊、舊 API 與新增顏色方法、升級及回復需在隔離環境測試；不得修改使用者主機 COM 登錄。測試未通過或必要相容性驗證受阻，停止新包交付；不把前版測試代替本版。按需求先測試並檢查範例及手冊，再打包。
5. 手冊說明產品／組件／檔案版本與升版方式；維持既有安裝畫面，透過 DLL 檔案屬性與同版打包報告查詢新版檔案版本。

## 適用性
架構：適用（版本與 COM 安裝契約）；系統整合：適用（x86／x64 COM 與既有客戶端）；UI：不適用（本次不改安裝畫面）；資料庫：不適用（無產品資料庫變更）；維運：不適用（無新增常駐服務，版本與回復交接納入文件）。效能目標未提供。程式目錄 `src/Excelopen`；固定測試包 `publish/Installer/Setup`。
