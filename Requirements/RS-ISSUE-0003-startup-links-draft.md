# 安裝程式啟動頁快捷連結方案草案｜ISSUE-0003

狀態：待使用者確認；Codex 擔任 PM、SA、設計、系統整合與維運，屬自查。此方案擴充原完成頁入口，沿用 ISSUE-0003 L3。

## 目標與建議介面

安裝程式歡迎頁顯示三個可直接點擊的超連結：LibreOffice 安裝版下載頁、LibreOffice 免安裝版下載頁，以及開啟已安裝的 ExcelKit 資料夾。點擊當下開啟對應頁面或資料夾；使用者可以直接取消／關閉安裝精靈，不需執行安裝。使用中英文標準文字，按鍵盤可操作。既有完成頁三個預設不勾選的入口及安裝資料夾連結文字檔保留。

資料夾入口只在能從 ExcelKit 安裝記錄辨識已安裝路徑且該目錄存在時啟用；無法辨識時顯示「尚未偵測到 ExcelKit 安裝資料夾」，不推測或建立目錄、不將安裝程式所在資料夾誤認為安裝目錄。安裝記錄查詢須涵蓋支援的 32／64 位元視圖，衝突或無法確認時不開啟並提示。檢查路徑與開啟不得寫入 COM 或其他設定。

現有 InitializeSetup 在建立精靈前檢查 .NET Framework 4.7.2；為讓缺少前置條件者也可查看下載頁，建議將檢查移至準備安裝之前，失敗則停止安裝、提示原有訊息，靜默安裝同樣不得繼續。此變更需驗證前置條件不符合時沒有複製檔案或修改 COM 登錄。原有管理員權限提示仍可能在歡迎頁前出現；若要免管理員開啟入口須另行評估，不納入此方案。

## 判定與比較

- 架構：適用，移動安裝前置條件檢查時機，需 SA 評估及失敗回復回歸；不降低真正安裝的條件。
- UI：適用，歡迎頁連結與狀態提示須支援中英文及鍵盤；採現有精靈視覺。
- 資料庫：不適用，不變更應用資料庫。
- 系統整合：適用，外部瀏覽器及 Windows 安裝記錄需驗證；不可猜測安裝路徑。
- 維運：適用，需確認升級、舊版／缺失／多筆紀錄及故障回復。
- 替代方案：維持完成頁無法滿足只查看的情境；另外提供獨立啟動工具會擴大程式與維護範圍，故優先在歡迎頁顯示。

## 驗收草案

1. 開啟安裝程式後，在歡迎頁可分別開啟兩個下載頁；取消後沒有執行安裝或變更既有 COM 註冊。
2. 已安裝且路徑可確認時可直接開啟正確資料夾；未安裝、路徑不存在或資料衝突時有明確提示，不建立資料夾、不開啟錯誤位置。
3. 缺少 .NET Framework 時仍能顯示歡迎頁及下載連結，但繼續安裝時必須停止，且不得複製檔案或修改 COM；靜默安裝同樣停止。
4. 完成頁既有三個選項、資料夾連結檔及手冊／媒體／範例預設值不退化；依測試計畫測試成功、失敗回復、升級、移除與 x86／x64。實際無法驗證者標未執行。
5. 保留 Installer 與 publish/Installer/Setup 作程式及固定測試輸出位置；測試版進版，正式版基準 1.2.4 不變。

方案待使用者確認；測試計畫及實作依核准版本更新。
## 2026-11-16 擴充草案：啟動時顯示 DLL 與安裝器版本

使用者希望啟動時看到系統中 DLL 的安裝狀態及與安裝程式的版本差異。建議在歡迎頁以唯讀方式分別呈現 x86／x64 COM 註冊狀態、已註冊 DLL 路徑及組件版本；另外顯示本安裝器版本及其內含 net472 DLL 組件版本，並標示兩者為不同版本欄位。可取得時顯示已安裝安裝器版本及 DLL 檔案／產品版本。明確區分未註冊、已註冊且檔案存在、檔案遺失、無法讀取、使用者層覆寫及多筆／不一致，未能確認時顯示未知，不把未註冊解讀為電腦上沒有任何 DLL，也不掃描整台電腦。

比對同類型版本：已註冊 DLL 的組件版本與套件內 DLL 組件版本比較；已安裝安裝器版本與目前安裝器版本分開顯示。版本相同不表示檔案內容相同；若以雜湊證實內容一致才標示一致，若未比對則明確顯示未驗證。涉及非數值的安裝器測試版字串時不憑 SemVer 的 build metadata 推論新舊。狀態唯讀且不影響現有安裝前衝突檢查、備份與使用者確認。

本機唯讀盤點：HKLM x86／x64 COM 均指向 C:/Program Files (x86)/ExcelKit/bin/net472/ExcelKit.DLL，檔案存在，組件及檔案版本均為 1.2.4.0；已安裝安裝器版本為 1.2.4+20261116102933。publish/bin/net472/ExcelKit.dll 的組件及檔案版本均為 1.2.4.0。此為盤點時狀態，不代表檔案雜湊一致或其他使用者的登錄狀態已驗證；本次暫存編譯版本 1.2.4+20261116104354，最終版本待核定。

新增驗收：乾淨機、僅一種位元、雙位元、不同版本、遺失 DLL、無法讀取、多版本及使用者層覆寫下呈現正確或明確顯示未知；不觸發 COM 建立或註冊、不改檔案或登錄；GUI、安裝、升級、靜默與失敗回復須在隔離環境測試。新需求及前述快捷連結與前置檢查時機一併等待人類確認。
